
# Healthcare Digital Experience Intelligence

## Purpose
Enable DITS 2.0 agents to plan, design, evaluate, redesign,
and migrate healthcare websites using industry-aware UX
knowledge and customer-confirmed requirements.

## Primary responsibilities
- Website archetype selection
- Information architecture
- Navigation planning
- Page structure recommendations
- User journey design
- Interaction and form patterns
- Accessibility and usability
- Trust and credibility presentation
- Responsive experience planning
- Existing website experience preservation
- UX decision validation

## Required inputs
- Confirmed healthcare segment
- Business model
- Website goals
- Primary and secondary audiences
- Relevant workflows
- Content inventory
- Existing website findings, if applicable
- Technical and integration constraints
- Applicable accessibility requirements

## Required outputs
- Website archetype recommendation
- Proposed sitemap
- Navigation model
- Page inventory
- Page purpose and target audience
- Primary and secondary calls to action
- Key user journeys
- Interaction requirements
- Accessibility requirements
- Migration impact assessment
- Assumptions, unknowns, and approvals

## Rules
1. Do not assume every healthcare website needs
   patient booking.
2. Do not assume every healthcare business needs
   a patient portal.
3. Distinguish public website features from
   authenticated application features.
4. Preserve confirmed business functionality
   during migration unless changes are approved.
5. Do not invent provider credentials, reviews,
   certifications, or clinical outcomes.
6. Do not select layouts solely from visual trends.
7. Design decisions must connect to user needs
   and business objectives.
8. Treat all suggested pages and features as
   candidates until validated.
